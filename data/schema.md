# MSX Models DB — Data Schema

## Overview

All model data is stored in `docs/data.js`, which sets `window.MSX_DATA` when loaded via a `<script>` tag. The TypeScript types are defined in `src/types.ts`; the serialiser is `build()` in `scraper/build.py`.

The file is generated by the scraper (`python -m scraper build`) and committed to the repository. `npm run build` preserves an existing `docs/data.js` when it rebuilds `docs/` (see `preserveDataJs` in `vite.config.ts`); it does not create one.

---

## MSXData (root object)

| Field | Type | Description |
|---|---|---|
| `version` | `number` | Schema version integer. Currently `1`. Increment on breaking changes. |
| `generated` | `string` | ISO date (`YYYY-MM-DD`) of when the file was generated. |
| `groups` | `GroupDef[]` | All group definitions. |
| `columns` | `ColumnDef[]` | Active column definitions (neither `hidden` nor `retired`), in display order. |
| `models` | `ModelRecord[]` | All model records, sorted by `id`. |
| `slotmap_lut` | `Record<string, string>` | Slot-map abbreviation → tooltip text (compacted from `data/slotmap-lut.json`). Optional in the TS type for legacy files; always written by the scraper. |
| `defaultView` | `DefaultViewConfig?` | Optional default view. Not currently emitted by the scraper; omitted = show all. |

## ColumnDef

Optional fields are only serialised when set (non-empty / `true` / `> 0`), to keep `data.js` compact.

| Field | Type | Description |
|---|---|---|
| `id` | `number` | **Stable integer ID.** Permanently assigned in `scraper/columns.py`. Never reassigned or reused. `0` is reserved. |
| `key` | `string` | Machine-readable key (snake_case). |
| `label` | `string` | Display label (column picker, tooltips, copied headers). |
| `groupId` | `number` | ID of the `GroupDef` this column belongs to. |
| `type` | `'string' \| 'number' \| 'boolean'` | Data type of values in this column. |
| `shortLabel` | `string?` | Short header text (allows 2-line wrap). Falls back to `label`. |
| `tooltip` | `string?` | Header tooltip. Falls back to `label`. |
| `linkable` | `true?` | Cells may render as hyperlinks via `ModelRecord.links`. |
| `truncateLimit` | `number?` | Values longer than this are clipped to `(limit − 1)` chars + `…`; full value shown in a tooltip. |
| `shaded` | `true?` | Cells render with a tinted background and bold text. |
| `maxWidth` | `number?` | Max width of data cells in px; overflow is ellipsised with a hover tooltip. Absent = the shared stylesheet cap (160px). |
| `sortLast` | `string[]?` | Values that sort after all other values (but before blanks), in both directions — e.g. `"None"` in the Engine columns. |
| `defaultOff` | `true?` | Column ships and is toggleable, but starts hidden on a fresh load (and after "Reset view"). Absent = starts visible. |

### Column catalogue

The authoritative list of columns — IDs, keys, labels, groups, and the Python-only flags `hidden` (scraped and usable by `derive`, but not shipped), `retired` (permanently removed, ID kept) and `derive` (computed columns) — lives in **`scraper/columns.py`**. It is intentionally not duplicated here.

Slot-map columns: 64 columns (4 main slots × 4 sub-slots × 4 pages) with keys `slotmap_{ms}_{ss}_{page}`, in groups 8–11.

## ModelRecord

| Field | Type | Description |
|---|---|---|
| `id` | `number` | **Stable integer ID** from `data/id-registry.json`. Never reassigned or reused. |
| `values` | `(string \| number \| boolean \| null)[]` | Field values, positionally aligned with `MSXData.columns[]`. |
| `links` | `Record<string, string>?` | Hyperlink URLs keyed by column key (`model` → msx.org wiki page, `openmsx_id` → openMSX machine XML on GitHub). May be inherited from a donor model via `data/link-shares.json`. |
| `tooltips` | `Record<string, string>?` | Cell tooltips keyed by column key, shown on hover whether or not the text is clipped. Emitted from hidden columns flagged `tooltip_for` in `scraper/columns.py` (e.g. the scraped Engine text behind the two parsed Engine columns). |

### values[] alignment rule

`model.values[i]` corresponds to `MSXData.columns[i]`. The arrays **must** be the same length. If a value is unknown or not applicable, use `null` — never omit the entry or use `undefined`.

### Slot-map cell values

Slot-map cells hold an abbreviation from `slotmap_lut` (e.g. `MAIN`, `DSK`, `CS1`), optionally with a suffix. The symbols are configured under `slotmap_symbols` in `data/scraper-config.json` (read by `scraper/symbols.py` and `src/symbols.ts`):

| Config key | Meaning |
|---|---|
| `absent` | Sub-slot physically absent (slot not expanded) |
| `empty_page` | Sub-slot exists but no device is mapped on this page |
| `mirror_suffix` | Appended to an abbreviation for a mirrored page (e.g. `DSK*`) |
| `subslot_suffix` | Appended to `CS`/`ES` when the slot sits inside a sub-slot (e.g. `CS1!`) |

The `absent` and `empty_page` symbols also appear as `__sentinel__` rules in `data/slotmap-lut.json` so they get tooltips; the two files must agree (enforced by `tests/scraper/test_slotmap_lut.py`).

## IDRegistry (`data/id-registry.json`)

The ID registry is maintained by the scraper and committed to the repository. It is **not** shipped to the browser. Column IDs are defined in `scraper/columns.py`, not here.

| Field | Type | Description |
|---|---|---|
| `version` | `number` | Registry format version. Currently `2`. |
| `models` | `Record<string, number>` | Natural key → stable model ID. Natural key: `"<manufacturer>\|<model>"` (lowercase, trimmed). |
| `retired_models` | `number[]` | Model IDs retired when a model is removed. Never reused. |
| `next_model_id` | `number` | Next ID to assign for a new model. Only increases. |

### Stable ID contract

- IDs are short positive integers starting at 1.
- Once assigned, an ID is **permanent** — it identifies the same entity forever.
- Retired IDs are recorded in `retired_models` but **never reused**.
- `next_model_id` only ever increases.
- The scraper must attempt to **match before create**: match incoming data to an existing registry entry (by natural key) before assigning a new ID.

|---|---|---|

## Versioning

The `MSXData.version` field enables future schema evolution:

- **Additive changes** (new columns with new IDs, new optional fields): no version bump required.
- **Breaking changes** (column removed, type changed, values[] alignment changed): bump `version`.
- The URL codec has its own version byte (independent of `MSXData.version`). Both are checked at decode time and fall back to defaults on unknown versions.
